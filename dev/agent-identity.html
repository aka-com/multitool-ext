Agent identity — show verified names, drop the rest

Today every surface renders the agent's self-reported x-multitool-client label (daemon/mod.rs:281), wrapped in .untrusted-identity with a "self-reported" tooltip carrying the entire disclaimer. This proposal stops rendering that label anywhere a decision is made: if the OS verified the caller, show the real name with a check; if not, say an agent and show nothing else. Pick a state below — every proposed surface on this page re-renders.

State

The whole modelThree states, one rule

The rule: Multitool only prints a name it can vouch for. That collapses four assurance tiers into three renderings, and removes the quoting convention, the tier vocabulary, and the bidi isolation that existed only to make hostile names safe to display. Click a card to switch the whole page into that state.

Surface 1Traffic-confirmation sheet

The sheet titles with approvalAgentName(agent) (app.tsx:5988) and repeats the label in an Agent fact row (app.tsx:5998). Both are the agent's own string, at the exact moment a human is deciding whether to trust it.

Proposal: the title names the caller only when the OS did. Otherwise it says this agent, and the Agent row states what was verified, with the evidence one click deeper.

Surface 3Activity log — the one place dropping the name costs something

Rows carry reported as "{entry.agent}" (app.tsx:4129) and the Agent filter lists those strings (app.tsx:4391). Here the premise "the user knows who is prompting them" does not hold: reviewing history a week later is exactly when you cannot remember, and "an agent" on every row makes the log useless for correlation.

Proposal: replace the self-reported name with the broker's own session id — already minted as a UUID at mcp_host.rs:645 — shortened to a handle. It is ours, so it is trustworthy, and it does the job the label was really doing: telling one run apart from another. Group the filter by verified program, then by session.

Why this is smaller than it looks

  • It deletes code rather than adding it. The quoting convention, the tier vocabulary, the .untrusted-identity wrapper on agent names, the "self-reported" tooltips, and agentLabel()/shortAgent()/approvalAgentName() all collapse into one helper returning either a verified name or the word "agent".
  • There is nothing left to spoof. The rename switch is the whole security argument: with no slot for caller-chosen text, no amount of cleverness in the label reaches a decision surface. Compare that to defending a rendering of hostile text forever.
  • The label is still recorded, just not displayed. It stays in the audit entry (AuditEntry.agent) for forensics — the change is that Multitool stops repeating it back to the user as if it meant something.
  • Agent-supplied text does not vanish entirely. The requested service in a connect request and the raw request body are still the agent's words, so .untrusted-identity stays for those. It just stops being applied to identity.

The one real cost, stated plainly

If you run several unverified agents at once, live surfaces can no longer tell them apart — two simultaneous prompts both say "An agent". The session handle fixes this for history but not for a glance. If that bites, the smallest honest addition is the same handle on live surfaces ("An agent · 3f2a"), which is broker-assigned and therefore still not something a caller can choose.
