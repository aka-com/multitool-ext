aka — CLI redesign walkthrough

The proposed pre-launch command surface, shown as the golden paths each persona actually walks. Personas are ordered by how often their loops run. Pick a flow and step through it; the terminal accumulates a real session. The Interactivity toggle compares a flags-only “soft” surface against the prompt-driven “guided” one — same command tree either way.

The keystone: one ambient context. Every command resolves its broker the same way — --broker <name-or-url> flag → AKA_BROKER env → repo pin file (walk up from cwd, like vercel link) → the aka use default → local auto-detect (~/.aka, then ~/.akaserver). This deletes --root/--broker from twenty command signatures and makes the hot path work against remote brokers, which today are unreachable from dsn/ssh/mcp (socket-only). Verbs for the daily loop, nouns for management, and everything privileged under one word: admin. Interactivity is a dial, not a commitment: this tree reads as the soft level — flags-only, scaffold errors instead of forms, print-by-default setup — and the guided upgrades (dashboard, wizard add, setup that writes) can layer on later without renaming anything.
